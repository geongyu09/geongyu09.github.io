# AI를 활용하여 글의 개요 작성하는 커맨드(스킬)

이 커맨드는 AI를 활용하여 글의 개요를 작성합니다.

## 이 커맨드가 하는 일

1. 프롬프트에 입력된 내용을 파악해 사용자가 글을 작성하기 위해 생각하고 있는 방향성이나 지금까지 나왔던 고민/내용들을 파악합니다.
   1-1. 사용자가 크게 말을 하지 않았다면: 사용자에게 글의 방향성, 독자, 전달하려는 메시지 등 글을 작성하기 위해 필요한 핵심 요소들을 다음 단계에서 질문해야합니다.
2. 작성 내용을 바탕으로 방향성, 독자, 전달하려는 메시지 등 블로그 글을 작성하기 위하여 필요한 핵심 요소들을 파악하고 필요한 정보를 사용자에게 질문하여 수집합니다.
3. 파악한 핵심 요소들과 수집한 정보를 바탕으로 글의 구성된 초안을 작성합니다.
4. 작성된 초안을 `./on-writing/outline.md` 파일에 업데이트합니다.

## 결과 예시

```markdown
# 글 제목

"LLM은 어떻게 개발자가 되는가 — Claude Code라는 하네스의 해부"

## 대상 독자

- LLM에 대해서 관심이 있는 사람
- Claude Code라는 프로젝트에 관심이 있거나 사용해본 적 있는 사람

## 전달하려는 메시지 / 담고싶은 내용

- Claude Code가 Claude 모델을 어떻게 하네스 하여 실제 세상에 영향을 주고, 실제로 개발자처럼 일할 수 있게 만드는가에 대한 정보 전달

## 글 방향성

[도입]

- Claude Code를 처음 썼을 때의 인상 ("모델이 똑똑한 건가?")
- 그런데 써보니 단순히 모델이 똑똑한 게 아니라는 의심
- 이 글의 질문: "Claude Code는 LLM을 어떻게 하네스하는가?"

[1부: 하네스라는 개념]

- 모델(뇌) vs 하네스(몸) 비유
- 공식 문서가 쓰는 정확한 표현: "Claude Code는 Claude 주변의 에이전트 하네스 역할을 한다"
- 하네스가 없으면 LLM은 그냥 텍스트 생성기

[2부: 에이전트 루프 — 하네스의 심장]

- 컨텍스트 수집 → 작업 수행 → 결과 검증
- 이 루프가 "개발자처럼 일한다"의 본질
- JS 개발자라면 익숙한 비유로: setInterval이 아니라 while (!done) 같은 것

[3부: 도구 — 하네스의 손발]

- 내장 도구 5가지 카테고리
- "도구가 없으면 Claude는 텍스트만 뱉는다"
- 도구 호출(tool use)의 메커니즘 — 여기서 살짝 API 레벨의 이야기

[4부: 컨텍스트 관리 — 하네스의 뇌 보호 장치]

- LLM은 컨텍스트 윈도우가 유한하다
- CLAUDE.md, skills, subagents, 자동 압축
- 이게 왜 "하네스의 공학적 기여"인지

[5부: 확장 계층 — 하네스를 확장하기]

- Skills, MCP, Hooks, Subagents
- 각자 에이전트 루프의 어디에 끼어드는가
- 독자가 직접 만질 수 있는 부분

[6부: 리버스 엔지니어링의 관점 — 공식 문서 너머]

- 커뮤니티가 분석한 것들 (system prompt 유출, 도구 호출 방식 추정)
- 여기선 신중하게 "추정이다"를 명시하면서
- 실제 의사결정 (예: 왜 CLAUDE.md를 매 요청마다 로드하는가)

[결론]

- 하네스의 관점에서 본 Claude Code의 설계 철학
- LLM 시대의 "애플리케이션"은 이렇게 만들어진다
- 다음 글 예고 (있다면)
```
