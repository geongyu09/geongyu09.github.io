# 블로그 글에 벡터 이미지(SVG) 생성 및 삽입

이 스킬은 `_posts/`의 블로그 글을 읽고, 개념 설명·흐름·구조 비교 등 **글만으로는 전달이 어려운 부분**에 SVG 다이어그램을 직접 그려서 삽입합니다.

## [금지] 글 본문 수정 금지

이 스킬이 글 파일에 가할 수 있는 변경은 **이미지 마크다운 한 줄의 삽입뿐**입니다.

- 기존 문장을 수정, 추가, 삭제, 재배치하지 않습니다. (오타 수정 포함)
- 이미지에 대한 해설 문장을 임의로 추가하지 않습니다. 해설이 필요하다고 판단되면 사용자에게 제안만 합니다.
- `tone-and-manner` 스킬을 로드하거나 적용하지 않습니다.

## 작업 절차

### 1. 대상 글 확인

- 사용자가 글을 지정하지 않았다면 어떤 글인지 확인합니다.
- 글 전체를 읽고 이미 존재하는 이미지들(위치, 내용)을 파악합니다. 이미 이미지가 충분한 구간에는 추가하지 않습니다.

### 2. 삽입 지점 선정

다음과 같은 구간이 좋은 후보입니다.

- 여러 단계의 **흐름/순서**를 산문으로 설명하는 구간 (요청 흐름, 렌더링 파이프라인 등)
- 두 가지 방식·구조를 **비교**하는 구간 (before/after, A방식 vs B방식)
- **구조/관계**를 설명하는 구간 (컴포넌트 트리, 레이어 구조, 의존 관계)
- 좌표·크기·움직임 등 **시각적 개념**을 설명하는 구간 (애니메이션 방향, 레이아웃)

반대로 다음 구간에는 넣지 않습니다.

- 코드 블록이 이미 충분히 설명하는 구간
- 감정·회고 서술 구간
- 한 문장으로 끝나는 단순 사실 서술

### 3. 계획 승인 받기

이미지를 생성하기 전에 사용자에게 계획을 보여주고 승인을 받습니다.

- 각 후보마다: **삽입 위치**(섹션명 + 기준 문장), **이미지가 표현할 내용**(어떤 다이어그램인지 한두 문장)
- 사용자가 명시적으로 "알아서 넣어줘"라고 한 경우에만 승인 절차를 생략할 수 있습니다.

### 4. SVG 생성

아래 [SVG 스타일 가이드]를 따라 SVG 파일을 직접 작성합니다.

- 저장 위치: `public/assets/blog/[글 제목]/[설명적-이름].svg`
  - `[글 제목]`은 해당 글의 기존 에셋 폴더명을 그대로 따릅니다. 폴더가 없으면 글 파일명(카멜케이스)으로 만듭니다.
  - 파일명은 숫자 패턴(`0.png`, `1.png`...)과 겹치지 않도록 내용을 설명하는 케밥케이스 영문명을 씁니다. 예: `render-flow.svg`, `stack-vs-tab.svg`
- 작성 후 well-formed 여부를 검증합니다: `xmllint --noout [파일]` (없으면 `python3 -c "import xml.dom.minidom, sys; xml.dom.minidom.parse(sys.argv[1])" [파일]`)

### 5. 글에 삽입

승인된 위치에 이미지 마크다운 라인만 삽입합니다.

```markdown
![한글로 된 설명적 alt 텍스트](/assets/blog/[글 제목]/[파일명].svg)
```

- alt 텍스트는 "무엇을 보여주는 이미지인지"를 한글로 설명적으로 작성합니다. 예: `![스택 네비게이션의 화면 전환 흐름](/assets/blog/appLikeWeb/stack-flow.svg)`
- 문단과 문단 사이에 빈 줄을 사이에 두고 삽입합니다. 문단 중간을 쪼개지 않습니다.

### 6. 확인 및 보고

- `bun dev`로 확인을 원하는지 사용자에게 안내하거나, 이미 개발 서버가 떠 있으면 해당 글 경로를 알려줍니다.
- 생성한 파일 목록과 삽입 위치를 보고합니다.

## SVG 스타일 가이드

이 블로그의 렌더링 환경에 맞춘 규칙입니다. 반드시 지킵니다.

### 렌더링 환경 제약

- 이미지는 `next/image` + `rounded-xl` 카드 스타일로 렌더링되며 최대 높이 600px로 표시됩니다.
- **다크모드가 class 기반 토글이라 SVG가 테마를 감지할 수 없습니다.** 따라서 SVG는 반드시 **명시적인 배경 사각형**을 가져야 합니다. 투명 배경 금지.
- 외부 폰트, 외부 이미지 참조, `<script>`, `<foreignObject>` 금지. 순수 shape + `<text>`만 사용합니다.

### 기본 골격

```svg
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 800 450" width="800" height="450" font-family="-apple-system, 'Apple SD Gothic Neo', 'Pretendard', 'Noto Sans KR', sans-serif">
  <rect width="800" height="450" fill="#fafafa" rx="12"/>
  <!-- 내용 -->
</svg>
```

- `viewBox`와 `width`/`height` 속성을 모두 명시합니다. (Img 컴포넌트가 width/height를 읽습니다)
- 비율은 내용에 맞게 조절하되 가로형(4:3 ~ 16:9)을 기본으로 합니다.

### 색상 팔레트

배경 `#fafafa` 위에서 다음 팔레트를 사용합니다.

| 용도 | 색 |
| --- | --- |
| 배경 | `#fafafa` |
| 박스 채우기 | `#ffffff` (테두리 `#d4d4d8`) |
| 강조 박스/포인트 | `#3b82f6` (채우기는 `#dbeafe`) |
| 보조 강조 | `#f59e0b` (채우기는 `#fef3c7`) |
| 성공/결과 | `#10b981` (채우기는 `#d1fae5`) |
| 본문 텍스트 | `#27272a` |
| 보조 텍스트 | `#71717a` |
| 화살표/연결선 | `#a1a1aa` |

- 한 이미지에 강조색은 1~2개만 씁니다. 알록달록하게 만들지 않습니다.

### 도형과 텍스트

- 박스는 `rx="8"` 정도의 둥근 모서리, `stroke-width="1.5"`.
- 화살표는 `<marker>`로 정의한 화살촉을 재사용합니다.
- 텍스트 레이블은 **한글**로 작성합니다. 코드 식별자(`<StackLink />` 등)는 원문 그대로 씁니다.
- 폰트 크기: 제목급 20~24px, 레이블 14~16px, 보조 설명 12~13px. viewBox 800 기준이며, 이보다 작아지면 블로그에서 읽기 어렵습니다.
- 텍스트가 박스를 넘치지 않도록 여유 있게 배치합니다. 한글은 글자당 대략 폰트 크기만큼의 폭을 차지한다고 계산합니다.

### 톤

- 깔끔한 기술 다이어그램 톤을 유지합니다. 그라데이션, 그림자 필터, 3D 효과를 쓰지 않습니다.
- 작성자가 손그림 "형상 그림"을 즐겨 쓰는 만큼, 지나치게 기계적인 완벽함보다는 **여백이 넉넉하고 요소가 적은** 단순한 구성을 지향합니다. 한 이미지에 담는 개념은 하나입니다. 복잡하면 두 장으로 나눕니다.
