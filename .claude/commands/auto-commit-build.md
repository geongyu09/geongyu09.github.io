# 자동 커밋 & 빌드 커맨드

현재 워킹 디렉토리의 변경사항을 커밋하고 푸시한 뒤, 빌드까지 한 번에 수행하는 커맨드입니다.

## 진행 순서

### 1. commit 스킬 실행

`commit` 스킬(Skill 도구로 `commit` 호출)을 실행하여 다음을 수행합니다.

- 변경사항 확인 (`git status`, `git diff`, `git diff --staged`, `git log -n 5 --oneline`)
- 기존 커밋 컨벤션에 맞는 커밋 메시지 작성

단, **이 커맨드에서는 commit 스킬의 승인 대기 규칙을 다음과 같이 오버라이드합니다.**

- **커밋 분리가 가능한 경우**: 스킬이 커밋 분리 방향을 제시하면, 사용자에게 묻지 않고 **제시된 방향대로 커밋을 쪼개서** 순서대로 커밋합니다.
- **커밋 분리가 불필요한 경우**: 사용자 승인을 기다리지 않고 **즉시 커밋을 진행**합니다.
- 어떤 경우에도 사용자에게 확인을 요청하거나 대기하지 **않습니다**. 제안 내용은 진행 상황 보고로만 출력합니다.

### 2. 커밋 및 푸시

- 각 커밋마다 해당하는 파일만 `git add`한 뒤 `git commit -m "<메시지>"`를 실행합니다.
- 커밋 메시지에 `Co-Authored-By` 트레일러나 Claude/생성 도구 관련 서명은 **절대 추가하지 않습니다.**
- `git branch --show-current`로 현재 브랜치를 확인하고 `git push origin <현재 브랜치>`로 푸시합니다.
- **현재 브랜치가 `dev` 등 보호 브랜치로 추정되더라도 재확인 없이 바로 푸시합니다.** (commit 스킬의 보호 브랜치 재확인 규칙을 오버라이드)
- 원격 브랜치가 없는 경우 `git push -u origin <현재 브랜치>`로 upstream을 설정하며 푸시합니다.
- push가 rejected되거나 충돌이 발생하면 `--force`를 사용하지 않고 상황을 보고한 뒤 중단합니다.

### 3. 빌드

푸시가 성공하면 빌드를 실행합니다.

```bash
bun run build
```

- 빌드가 실패하면 실패 로그의 핵심 원인을 정리하여 보고합니다. 코드를 임의로 수정하지 않습니다.

### 4. 결과 보고

모든 단계가 끝나면 다음을 요약하여 보고합니다.

- 생성된 커밋 목록 (해시 + 메시지)
- 푸시된 브랜치
- 빌드 성공/실패 여부

## 주의사항

- 이 커맨드는 코드를 작성하거나 수정하지 않습니다. git 동작과 빌드만 수행합니다.
- 변경사항이 없으면 커밋/푸시를 건너뛰고 그 사실을 보고한 뒤 종료합니다.
