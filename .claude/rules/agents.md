### 문장을 의미없이 짧게 쓰기 -> 긴 문장 쓰기
제발 길게 써라 제발 길게 써라 제발 길게 써라 제발 길게 써라 제발 길게 써라 제발 길게 써라
문장은 육하원칙에 맞춰서 이전 문장과 이후 문장이 하나의 맥락을 가진다면 무조건적으로 연결해서 길게 쓰세요. 

차이는 클래스가 자동으로 해주는 부분입니다. new 강제(IsClassConstructor), # private 공식 지원 등입니다. // ❌
-> 차이는 클래스가 자동으로 해주는 new 강제(IsClassConstructor), # private 공식 지원 등이 있습니다. // ✅

클래스 기반에서 이미 만들어진 인스턴스는 이렇게 부모를 바꿔도 영향받지 않습니다. 복사본이기 때문입니다. // ❌
-> 클래스 기반에서 이미 만들어진 인스턴스는 복사본이기 때문에 이렇게 부모를 바꿔도 영향받지 않습니다. // ✅

밖에서는 잘 돌던 모델이라 이번에도 당연히 될 줄 알았다. 그런데 안 돌아갔다. // ❌
-> 밖에서는 잘 돌던 모델이라 이번에도 당연히 될 줄 알았는데, 안 돌아갔다. // ✅

monolith 에이전트가 백그라운드에서 윤문 중입니다. 완료되면 알림을 받아 결과를 전달하겠습니다. // ❌

### 요약 선언문 뒤에 그 내용의 구체 묘사를 반복하지 않기

바로 뒤에 이어지는 구체 묘사가 보여줄 내용을 "~한 환경이었다", "~한 자리였다" 같은 요약 문장으로 먼저 선언하지 않는다. 묘사가 먼저 말하게 하고, 평가·요약이 필요하면 묘사 뒤에 한 번만 둔다. 같은 대상을 "~이었다/~였다" 규정문으로 두 문장 연속 서술하는 것도 금지한다.

치열하게 공부하고, 만나서 발표하고 토론하는 활동이었다. 각자가 몰입할 수 있는 환경이었다. 다들 자기 자리에서 몰두해 공부하고, 막히면 질문하고, 함께 풀어나갔다. // ❌ (규정문 연속 + 요약 선언을 다음 문장이 그대로 반복)
-> 치열하게 공부하고, 만나서 발표하고 토론하는 활동이었다. 다들 자기 자리에서 몰두해 공부하다가, 막히면 질문하고 함께 풀어나갔다. // ✅ (묘사가 대신 말한다)

### 의미없는 말 사용

설명 중 "이름이 비슷해 혼동하기 쉽습니다. 둘은 방향이 다릅니다." 문장 사용. 
-> 설명 중이라면 설명만. 혼동하기 쉽다는 것은 독자가 판단

### 뜻이 올바르지 않은 단어 사용하기

1. 발표를 가른다.
  - 발표를 어떨게 갈라?
2. 손에 잡히는 기준
  - 기준이 어떻게 손에 잡힘?
3. 백엔드와 객체지향을 처음 제대로 만나다
  - 백엔드, 객체지향이 사람이 아닌데, 어떻게 만남?

### 너무 딱딱한 표현

-> "프로토타입 기반"은 이렇다고 말할 수 있다.
